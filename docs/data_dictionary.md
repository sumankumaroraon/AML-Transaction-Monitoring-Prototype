# Data dictionary

All data is **synthetic**, generated by `src/01_generate_data.py` (seed 42). No real customer records are used.
Monitoring period: **2025-01-01 → 2025-12-31**.

## `data/raw/customers.csv` — 1,000 rows
| Column | Type | Description |
|---|---|---|
| customer_id | text | `C00001`… Primary key |
| occupation | text | One of 11 occupations (Student, Retail Worker, Teacher, Nurse, Software Engineer, Contractor, Retiree, Physician, Property Owner, Small Business Owner, Restaurant Owner) |
| customer_segment | text | `retail` or `business` |
| expected_monthly_activity_usd | number | Monthly activity declared at onboarding (KYC profile), rounded to $500. Drawn from an occupation-specific range |
| account_opening_date | date | Start of the customer relationship. ~8% of customers were onboarded during 2025 |

## `data/raw/accounts.csv` — 1,458 rows
| Column | Type | Description |
|---|---|---|
| account_id | text | `A000001`… Primary key |
| customer_id | text | FK → customers |
| account_type | text | `checking`, `business_checking`, or `savings` |
| open_date | date | Account opening date |

## `data/raw/transactions.csv` — 52,544 rows
| Column | Type | Description |
|---|---|---|
| transaction_id | text | `T0000001`… in time order. Primary key |
| timestamp | datetime | `YYYY-MM-DD HH:MM:SS` (loaded into SQLite as `ts`) |
| sender_account | text | Internal account (`A…`) or external party (see below) |
| receiver_account | text | Internal account (`A…`) or external party |
| amount | number | Amount in the original currency |
| currency | text | `USD`, `EUR`, `GBP`, `CAD` |
| amount_usd | number | Converted with fixed project FX rates (EUR 1.08, GBP 1.27, CAD 0.73) |
| transaction_type | text | See below |

**Transaction types:** `PAYROLL_DEPOSIT`, `ACH_CREDIT`, `ACH_DEBIT`, `BILL_PAYMENT`, `CARD_PURCHASE`, `P2P_TRANSFER`, `INTERNAL_TRANSFER` (own checking → savings), `CASH_DEPOSIT`, `CASH_WITHDRAWAL`, `WIRE_IN`, `WIRE_OUT`.

**External party prefixes:** `EXT-EMP` employer · `EXT-GOV-SSA` benefits · `EXT-ORG` external originator/payer · `EXT-MER` card merchant · `EXT-BIL` biller · `EXT-SUP` business supplier · `EXT-PAYROLL-PROC` payroll processor · `EXT-BEN` wire beneficiary · `CASH` cash counterparty.

## Ground-truth labels (used only for evaluation — never read by the rules)
### `data/labels/planted_scenarios.csv` — 44 rows
| Column | Description |
|---|---|
| scenario_id | `S001`… |
| scenario_type | `RAPID_PASS_THROUGH` (12), `ACTIVITY_SPIKE` (12), `MANY_TO_ONE` (8), `STRUCTURING` (12) |
| variant | `standard` (36) — clearly inside the intended pattern; `subtle` (8) — deliberately placed near or outside a threshold to test limits |
| subject_id | Account (or external beneficiary for MANY_TO_ONE) the scenario is about |
| customer_id | Owner of the subject account (blank for external beneficiaries) |
| window_start / window_end | First and last planted transaction |
| n_transactions / total_usd | Size of the scenario |
| description | Plain-English summary |

### `data/labels/planted_transactions.csv` — 284 rows
`scenario_id` → `transaction_id` for every planted suspicious transaction.

### `data/labels/benign_lookalikes.csv` — 19 rows
Legitimate activity designed to *resemble* a pattern (home sale / car purchase, community fundraiser, landlord rent collection, cash-intensive restaurant). Used to explain false positives.

## Outputs
| File | Description |
|---|---|
| `outputs/alerts.csv` | One row per alert: rule, subject, window, value, priority score/level, plain-English `reason`, `metrics_json` (observed values vs thresholds) |
| `outputs/alert_evidence.csv` | `alert_id` → `transaction_id` + `evidence_role` |
| `outputs/evaluation_summary.csv` | Precision / recall / alert volume, overall and per rule |
| `outputs/rule_coverage.csv` | Rule × planted pattern detection matrix |
| `outputs/recall_by_scenario_variant.csv`, `recall_by_scenario_type.csv` | Recall breakdowns |
| `outputs/scenario_detection.csv` | Every planted scenario with detected flag and the alerts/rules that caught it |
| `outputs/false_positive_breakdown.csv` | Unmatched alerts grouped by likely cause |
| `outputs/threshold_sensitivity.csv` | Alert volume / precision / recall when one parameter changes |
| `data/reviews/seed_reviews.csv` | Sample analyst reviews (status, disposition, note) loaded into `alert_reviews` |

## SQLite tables / views (`data/aml_monitoring.db`, built by `run_all.sh`)
`customers`, `accounts`, `transactions`, `planted_scenarios`, `planted_transactions`, `benign_lookalikes`, `alerts`, `alert_evidence`, `alert_reviews` · views `v_daily_volume`, `v_alert_queue`, `v_customer_monthly`.
